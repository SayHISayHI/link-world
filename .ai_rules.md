# Link World AI Agent Rules

This file mirrors the highest-priority project rules for AI coding tools that do not read `.cursorrules`.

## 1. Project Identity

Link World is a Local-first personal information asset system. It is not a simple bookmark manager. The product saves, parses, summarizes, evaluates, retrieves and resurfaces saved knowledge objects.

## 2. Required Reading Before Implementation

Before writing code, read the relevant docs:

- `docs/README.md`
- `docs/architecture.md`
- `docs/backend_architecture.md` for Rust/Tauri backend work
- `docs/frontend_architecture.md` for React work
- `docs/api_contracts.ts` for IPC contracts
- `docs/database_schema.sql` and `docs/database_migrations.md` for storage work
- `docs/state_machines.md` for lifecycle changes
- `docs/security_and_privacy_policies.md` for privacy/security work
- `docs/external_api_resilience.md` for network/model/API calls
- `tests/docs/testing_strategy.md` for testing expectations
- `docs/adr/` before changing foundational architecture decisions

## 3. Non-Negotiable Rules

- Frontend must not access SQLite, filesystem or secrets directly.
- Tauri commands must not contain business logic beyond validation, service call and error mapping.
- Rust services own state transitions and transaction boundaries.
- Repositories own SQL.
- All long-running work goes through background jobs.
- `parsed_documents` is the source of truth for parsed text.
- FTS/vector/cache are derived and rebuildable.
- API keys must be stored in OS keychain or encrypted secret store, never ordinary SQLite tables.
- Secret content must never be sent to third-party AI.
- Sensitive content requires explicit authorization before third-party AI.
- Evaluators are not just prompts; they must produce plans, evidence, verdicts and artifacts.
- Every stored AI output must be traceable through `ai_traces`.
- Every destructive operation must be auditable and purge derived data.

## 4. Tech Stack Constraints

- Desktop host: Tauri v2.
- Backend: Rust.
- Frontend: React 18+ with Vite and TypeScript.
- State management: Zustand.
- Styling: Tailwind CSS + shadcn/ui.
- Icons: lucide-react.
- Local DB: SQLite + FTS5.
- Optional semantic search: sqlite-vec behind feature flag.
- Model access: `ModelProvider` adapter with capabilities.

## 5. Testing Expectations

New implementation must include appropriate tests or fixtures:

- state transition tests.
- migration tests.
- error mapping tests.
- privacy policy tests.
- frontend loading/empty/failed state tests.
- evaluator JSON validity evals when prompts change.

## 6. Change Discipline

If a change modifies architecture, storage, API contracts, security policy, sync semantics, state machines or release process, update the corresponding docs and, if foundational, add or update an ADR.
